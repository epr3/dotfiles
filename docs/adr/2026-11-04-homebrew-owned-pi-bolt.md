# Install Pi-Bolt through Homebrew; keep pnpm Pi for rollback

Homebrew owns Pi-Bolt — opensec-git's compiled distribution of Pi — from its upstream tap: the Brewfile declares `tap "opensec-git/tap"` and unversioned `brew "pi-bolt"`, so normal `brew upgrade` keeps it current. There is no release pin, no repo-owned formula (its release archives and checksums change every release), and no mise involvement. The pnpm-Pi Bootstrap stage (`scripts/install-pi.sh`) is replaced by a guarded stage, `scripts/install-pi-bolt.sh`, run after `brew bundle`: it verifies the Homebrew-owned binary and reports the Pi-Bolt, bundled-Pi, and current `pi` versions; it never changes command resolution on a machine that already has a `pi` (see below). `scripts/install-pi-extensions.sh` and pnpm itself stay unchanged.

`pi` is a PATH-visible entry point managed by `scripts/pi-entrypoint.sh`: `activate` creates `"${XDG_DATA_HOME:-$HOME/.local/share}/pi/bin/pi"` as a symlink to `$(brew --prefix)/bin/pi-bolt`; `status` reports the current resolution; `deactivate` removes only our symlink. `.zshenv` exports `PI_ENTRYPOINT_DIR` (honoring a pre-set value) and prepends the directory to PATH only while the symlink exists, placed after the pnpm and mise blocks so the entry point wins in interactive Zsh and noninteractive `zsh -c` alike; direct executable invocation also resolves through PATH. So automated shell calls and direct executables reach the same agent as interactive shells.

Fresh machines (no `pi` on PATH, none at `${PNPM_HOME:-$HOME/Library/pnpm}/pi`) are activated by the guarded stage itself; on a machine with any prior `pi` the stage leaves resolution unchanged, prints the validate → activate → rollback steps, and the cutover is explicit: `scripts/pi-entrypoint.sh activate`. Rollback is `scripts/pi-entrypoint.sh deactivate`: it removes only the symlink whose target is Homebrew's pi-bolt, refuses to touch a foreign `pi`, and leaves the entry point directory and every local state alone; new shells fall back to the previous resolution (typically the pnpm Pi). The pnpm Pi (`~/Library/pnpm/pi`) is retained untouched so rollback keeps working. Curated Pi assets and machine-local Pi state (settings, sessions, credentials, extensions, context store) continue to be shared through `~/.pi/agent` unchanged: Pi-Bolt uses the same agent directory as Pi. The Pi runtime cache Pi-Bolt writes under `.pi/agent/cache/` stays out of version control via `.gitignore`.

A Pi-Bolt release is built on, and reports, a regular Pi version that may trail the previously installed Pi; version lag is reported and accepted when the agreed validation passes rather than treated as an automatic blocker.
