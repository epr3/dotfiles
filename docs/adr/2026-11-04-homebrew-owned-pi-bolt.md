# Install Pi-Bolt through Homebrew; keep pnpm Pi for rollback

Homebrew owns Pi-Bolt — opensec-git's compiled distribution of Pi — from its upstream tap: the Brewfile declares `tap "opensec-git/tap"` and unversioned `brew "pi-bolt"`, so normal `brew upgrade` keeps it current. There is no release pin, no repo-owned formula (its release archives and checksums change every release), and no mise involvement. The pnpm-Pi Bootstrap stage (`scripts/install-pi.sh`) is replaced by a guarded stage, `scripts/install-pi-bolt.sh`, run after `brew bundle`: it verifies the Homebrew-owned binary, reports the Pi-Bolt, bundled-Pi, and current `pi` versions, and never changes command resolution. `scripts/install-pi-extensions.sh` and pnpm itself stay unchanged.

`pi` becomes a PATH-visible entry point — a symlink to `$(brew --prefix)/bin/pi-bolt` — managed by a separate, explicit activation step (issue 02 of the [Pi-Bolt replacement spec](../../.scratch/pi-bolt-replacement/spec.md)), so automated shell calls and direct executables reach the same agent as interactive shells; this installation stage never activates it. The pnpm Pi (`~/Library/pnpm/pi`) is retained untouched so rollback keeps working. Curated Pi assets and machine-local Pi state (settings, sessions, credentials, extensions, context store) continue to be shared through `~/.pi/agent` unchanged: Pi-Bolt uses the same agent directory as Pi.

A Pi-Bolt release is built on, and reports, a regular Pi version that may trail the previously installed Pi; version lag is reported and accepted when the agreed validation passes rather than treated as an automatic blocker.
