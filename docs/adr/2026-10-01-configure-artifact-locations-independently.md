# Configure artifact locations independently

> **Superseded for upstream-derived skill instructions by the pinned-parity policy (2026-08-25).** The location mechanism and existing records remain intact, but their existence does not authorize skill-text forks. Only individually justified context-mechanism substitutions may differ from the pinned upstream content. Historical artifacts are not migrated by this decision.

`setup-context` records a destination per durable artifact class rather than deriving every output from one context home: glossaries, ADRs, the local issue board (including specs and maps), research, and explainers can each live in the code worktree or matching context worktree, with an explicit custom destination when needed. Preserve existing destinations by default; in context-repo setups, each chosen destination must stay branch-scoped so artifacts from different branches cannot collide. Repo-wide setup rules and conventions remain branch-independent under the context repo's `.agents/` (or the in-repo config home); temporary handoffs and reports remain in the OS temp directory. This adds configuration compared with a single context home, but avoids forcing unrelated outputs into one store or losing branch isolation when their locations diverge.
